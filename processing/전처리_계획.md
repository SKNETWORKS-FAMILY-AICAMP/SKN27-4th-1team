# 데이터 전처리 계획

## 목표

이번 작업의 목표는 원천 JSON 데이터를 바로 전처리하기 전에 먼저 데이터 상태를 분석하고, 그 결과를 바탕으로 본문 정리 규칙과 키워드 추출 방식을 확정하는 것이다.

최종적으로는 원본 데이터마다 구조가 다르더라도, 전처리 후에는 공통 컬럼 구조를 가진 processed 데이터를 만드는 것을 목표로 한다.

## 현재 원천 데이터

원천 데이터는 `database/raw` 폴더에 있다.

```text
database/raw/
  namu_asia_horror.json
  thering_horror.json
  ultimate_global_mythology_1000.json
```

각 데이터의 현재 판단은 다음과 같다.

| 파일 | 현재 판단 | 전처리 방향 |
| --- | --- | --- |
| `thering_horror.json` | `content`가 실제 괴담 본문으로 보임 | 본문 정리와 키워드 추출 우선 적용 |
| `ultimate_global_mythology_1000.json` | `description`, `behavior`, `history`, `signs`, `weakness` 등 설명 컬럼이 있음 | 여러 설명 컬럼을 합쳐 본문으로 사용 |
| `namu_asia_horror.json` | `content`에 스크립트/로딩 노이즈가 많은 것으로 의심됨 | 본문 사용은 보류하고, 재수집 또는 데이터 수정 후 처리 |

## reference 확인 및 반영

`reference` 폴더의 노트북을 확인한 뒤, 다음 개념을 전처리 코드에 반영한다.

| reference 파일 | 반영한 개념 | 연결된 코드 |
| --- | --- | --- |
| `2. Data Cleaning.ipynb` | 결측치 확인, 중복 확인, 문자열 정리, 정리 전/후 비교 | `analyze_raw_data.py`, `cleaning_rules.py`, `check_processed_quality.py` |
| `1. Pandas 기초.ipynb` | JSON/CSV 저장, records 형태 데이터 구성 | `preprocess_data.py` |
| `2. Pandas 심화.ipynb` | 컬럼 생성, 행별 처리 흐름, 조건 기반 처리 | `preprocess_data.py`, `check_processed_quality.py` |
| `2-1. Integer Encoding.ipynb` | 단어 빈도 기반 어휘 후보, 불용어 제외 | `keyword_extractor.py` |
| `2-2. 형태소 분석 & 어휘집 & Padding.ipynb` | 토큰화, 품사/명사 중심 후보 추출 흐름 | `keyword_extractor.py` |

현재 데이터는 `metadata` 안에 리스트와 딕셔너리를 보존해야 하므로, 실제 구현은 pandas DataFrame 대신 표준 `json` 라이브러리를 사용한다. 다만 처리 흐름은 reference의 데이터 클리닝, pandas 컬럼 처리, NLP 전처리 개념을 따른다.

## 전체 진행 순서

```text
1. 원천 데이터 분석
2. 제거할 문자와 노이즈 패턴 확인
3. 키워드 추출 가능성 확인
4. 파일별 전처리 정책 확정
5. processing 폴더에 전처리 코드 작성
6. database/processed 폴더에 전처리 결과 저장
7. 전처리 결과 품질 검토
```

## 1단계: 데이터 분석

먼저 `processing` 폴더에 분석용 파일을 둔다.

```text
processing/
  analyze_raw_data.py
```

이 파일은 데이터를 수정하지 않는다. 원천 데이터의 상태를 확인하고, 어떤 전처리를 해야 하는지 판단하기 위한 분석만 수행한다.

분석할 내용은 다음과 같다.

```text
파일별 데이터 개수
컬럼 목록
컬럼별 결측치
본문 후보 컬럼
텍스트 길이 분포
한글/영문 비율
특수문자 및 노이즈 패턴
HTML/스크립트/마크다운 링크 포함 여부
기존 keywords 컬럼 존재 여부
키워드 추출에 사용할 수 있는 메타데이터 컬럼
```

### 1단계 분석 완료 결과

`processing/analyze_raw_data.py`를 실행해 원천 데이터 분석 결과를 생성했다.

생성된 분석 결과 파일:

```text
database/processed/raw_data_profile.json
database/processed/raw_data_profile.md
```

분석 결과 요약:

| 파일 | 데이터 개수 | 추천 본문 상태 | 핵심 판단 |
| --- | ---: | --- | --- |
| `namu_asia_horror.json` | 128 | `needs_recrawl` | `content`가 실제 본문이 아니라 스크립트/로딩 노이즈에 가까움 |
| `thering_horror.json` | 45 | `valid_text` | `content`를 실제 괴담 본문으로 사용할 수 있음 |
| `ultimate_global_mythology_1000.json` | 1016 | `valid_text` | 설명성 컬럼들이 충분해 본문 구성 가능 |

따라서 2단계 이후 전처리 정책은 `thering_horror.json`과 `ultimate_global_mythology_1000.json`을 우선 처리하고, `namu_asia_horror.json`은 본문 전처리 대상에서 보류하는 방향으로 확정한다.

## 2단계: 제거 대상 분석

본문 정리 전에 원본 텍스트에서 어떤 노이즈가 반복되는지 확인한다.

확인할 제거 후보는 다음과 같다.

```text
#, /, [ ], ^ 같은 특수문자
[1], [2] 같은 각주 번호
마크다운 링크: [텍스트](URL)
일반 URL
HTML 태그
JavaScript 또는 CSS 로딩 문자열
반복 공백
불필요한 줄바꿈
분석에 방해되는 괄호나 기호
```

제거한 규칙은 나중에 `removed_patterns` 컬럼에 기록할 수 있어야 한다.

예시:

```python
removed_patterns = [
    "markdown_links",
    "citation_numbers",
    "special_chars: # / [ ] ^",
    "extra_whitespace"
]
```

## 3단계: 키워드 추출 가능성 분석

키워드 추출 전에는 각 데이터가 키워드를 뽑을 만큼 충분한 정보를 가지고 있는지 확인한다.

확인할 내용은 다음과 같다.

```text
본문 길이가 충분한가
본문이 실제 설명 텍스트인가
한국어/영어가 어느 정도 섞여 있는가
기존 keywords 컬럼이 있는가
title/name/category/tags/origin 같은 메타데이터가 있는가
본문에서 반복되는 주제어가 있는가
너무 일반적인 단어가 많이 나오는가
```

키워드는 단순히 많이 나온 단어가 아니라, 문서의 특징을 대표하는 단어 또는 짧은 문장을 뽑는 것을 목표로 한다.

키워드 추출 기준은 `keyword_basis` 컬럼에 기록한다.

예시:

```text
제목, 카테고리, 기존 태그, 본문에서 반복되는 명사, 사건/장소/의례/존재 유형을 기준으로 추출
```

## 4단계: 파일별 전처리 정책

아래 정책은 1단계 데이터 분석 결과를 바탕으로 확정한 1차 전처리 방침이다.

처리 우선순위:

```text
1순위: thering_horror.json
2순위: ultimate_global_mythology_1000.json
보류: namu_asia_horror.json
```

### thering_horror.json

`content`를 본문으로 사용한다.

예상 처리:

```text
description = content
cleaned_text = content 정리 결과
keywords = 기존 keywords + 본문/카테고리 기반 키워드
metadata = category, subcategory, date, horror_level, country 등
text_status = valid_text
```

확정 처리 방침:

```text
source = source
source_id = id
title = title
url = url
description = content
metadata = category, subcategory, country, horror_level, date, series_number, submitter, has_image
text_status = valid_text
```

제거할 노이즈:

```text
markdown_links
urls
square_brackets
extra_whitespace
repeated_newlines
```

키워드 추출 기준:

```text
기존 keywords 컬럼을 참고한다.
title에서 장소, 상황, 사건 단서를 참고한다.
category, subcategory를 키워드 후보로 활용한다.
본문에서 반복되거나 사건을 설명하는 핵심 명사를 추출한다.
너무 일반적인 단어는 제외한다.
```

### ultimate_global_mythology_1000.json

여러 설명 컬럼을 합쳐 본문으로 사용한다.

예상 처리:

```text
description = 원본 description
cleaned_text = description 정리 결과
keywords = name, origin, habitats, description 기반 키워드
metadata = origin, habitats, source_site 등
text_status = valid_text
```

확정 처리 방침:

```text
source = source_site
source_id = id
title = name
url = source_url
description = 원본 description
metadata = origin, habitats, source_site, behavior, history, signs, weakness, survival_rules
text_status = valid_text
```

주의할 점:

원본 `description` 안에 `behavior`, `history`, `weakness` 내용이 이미 포함되어 있는 경우가 많다. 따라서 여러 설명 컬럼을 단순히 합치지 않고, processed의 `description`에는 원본 `description`만 넣어 중복을 줄인다. `behavior`, `history`, `signs`, `weakness`는 삭제하지 않고 `metadata`에 유지한다.

metadata는 삭제 중심이 아니라 보존 중심으로 처리한다. 다만 metadata 안의 문자열과 리스트 값에도 반복 공백, 과도한 줄바꿈, URL, HTML 태그, 마크다운 링크 같은 명확한 노이즈가 있을 수 있으므로, 전처리 시 가벼운 문자열 정리를 함께 적용한다.

제거할 노이즈:

```text
square_brackets
special_symbols
extra_whitespace
repeated_newlines
urls
```

키워드 추출 기준:

```text
name을 핵심 키워드 후보로 사용한다.
origin, habitats를 주제 분류 키워드로 활용한다.
signs, weakness에서 특징적인 증상과 대처법을 추출한다.
description, behavior에서 존재 유형, 지역, 민간신앙 관련 표현을 추출한다.
```

전처리 결과 파일 이름은 헷갈리지 않도록 다음처럼 명확하게 한다.

```text
ultimate_global_mythology_processed.json
```

### namu_asia_horror.json

현재 `content`는 실제 본문이 아니라 스크립트 노이즈가 섞인 데이터로 의심된다.

따라서 초기 전처리에서는 본문 기반 처리를 보류한다.

가능한 처리 방향:

```text
1. 재수집 또는 데이터 수정 후 전처리
2. 임시로 title, primary_type, region, tags 기반 메타데이터만 처리
3. text_status를 needs_recrawl 또는 metadata_only로 기록
```

확정 처리 방침:

```text
본문 기반 전처리 대상에서는 제외한다.
최종 통합 processed 파일에도 초기에는 포함하지 않는다.
필요하면 별도 metadata_only 결과로만 저장한다.
재수집 또는 데이터 수정 후 주석을 풀어 처리한다.
```

메타데이터만 처리할 경우 사용할 수 있는 컬럼:

```text
source = source
source_id = id
title = title
url = url
metadata = primary_type, region, tags, habitat, gender
text_status = needs_recrawl 또는 metadata_only
```

코드를 작성할 때는 나중에 바로 활성화할 수 있도록 주석 처리 또는 옵션 방식으로 남긴다.

예시:

```python
DATASETS = [
    "thering_horror.json",
    "ultimate_global_mythology_1000.json",
    # "namu_asia_horror.json",  # 본문 데이터 확인 후 활성화
]
```

또는:

```python
PROCESS_NAMU = False
PROCESS_THERING = True
PROCESS_MYTHOLOGY = True
```

## 5단계: 전처리 코드 구조

전처리 코드는 `processing` 폴더에 작성한다.

추천 구조:

```text
processing/
  analyze_raw_data.py
  cleaning_rules.py
  keyword_extractor.py
  preprocess_data.py
  README.md
```

각 파일 역할:

| 파일 | 역할 |
| --- | --- |
| `analyze_raw_data.py` | 원천 데이터 분석, 전처리 전 데이터 품질 확인 |
| `cleaning_rules.py` | 제거 규칙과 본문 정리 함수 관리 |
| `keyword_extractor.py` | 키워드 추출 함수 관리 |
| `preprocess_data.py` | 전체 전처리 실행 |
| `README.md` | 실행 순서와 산출물 설명 |

## 6단계: processed 산출물 구조

전처리 결과는 `database/processed` 폴더에 저장한다.

추천 구조:

```text
database/
  raw/
    namu_asia_horror.json
    thering_horror.json
    ultimate_global_mythology_1000.json

  processed/
    raw_data_profile.md
    thering_horror_processed.json
    ultimate_global_mythology_processed.json
    integrated_horror_processed.json
    quality_report.md
```

`raw_data_profile.md`는 데이터 분석 결과를 사람이 읽기 편하게 정리한 보고서이다. 컬럼 선택과 전처리 정책을 정하는 근거 자료로 사용한다.

`quality_report.md`는 전처리 결과의 중복/반복 후보와 처리 기록을 정리한 보고서이다.

## 최종 공통 컬럼

전처리 결과는 가능한 한 다음 공통 컬럼을 가지도록 맞춘다.

```text
source
source_id
title
url
description
cleaned_text
description_length
cleaned_text_length
removed_patterns
noise_types
keywords
keyword_count
keyword_basis
text_status
metadata
```

컬럼 의미:

| 컬럼 | 의미 |
| --- | --- |
| `source` | 데이터 출처 |
| `source_id` | 원본 데이터의 ID |
| `title` | 문서 제목 또는 존재 이름 |
| `url` | 원본 URL |
| `description` | 정리 전 설명 본문 |
| `cleaned_text` | 정리 후 본문 |
| `description_length` | 정리 전 설명 본문 길이 |
| `cleaned_text_length` | 정리 후 본문 길이 |
| `removed_patterns` | 제거한 문자/패턴 목록 |
| `noise_types` | 원문에서 발견된 노이즈 유형 |
| `keywords` | 대표 키워드 |
| `keyword_count` | 추출된 키워드 개수 |
| `keyword_basis` | 키워드 추출 기준 |
| `text_status` | 본문 사용 가능 상태 |
| `metadata` | 원본의 부가 정보 |

`text_status` 값은 다음처럼 사용한다.

```text
valid_text      실제 본문 사용 가능
metadata_only   본문은 부족하지만 메타데이터 사용 가능
needs_recrawl   본문 재수집 또는 데이터 수정 필요
```

## 현재 기준에서 중요한 판단

이번 작업에서 가장 중요한 것은 바로 전처리를 실행하는 것이 아니라, 먼저 데이터 품질을 판단하는 것이다.

특히 `namu_asia_horror.json`처럼 본문 컬럼이 있어도 실제로는 스크립트 노이즈일 수 있으므로, 모든 파일에 같은 전처리 규칙을 무조건 적용하면 안 된다.

따라서 현재 계획의 핵심은 다음과 같다.

```text
데이터 분석
→ 제거 대상 확인
→ 키워드 추출 가능성 확인
→ 파일별 처리 정책 확정
→ 공통 컬럼 구조로 전처리
→ processed 폴더에 저장
```

## 이번 범위에서 제외할 것

이슈에서 스플리터는 일단 제외한다고 했으므로, 이번 계획에서는 RAG chunking 또는 splitter 작업은 하지 않는다.

이번 범위는 본문 정리와 키워드 추출까지로 제한한다.

## 7단계: 전처리 결과 품질 검토

processed 파일 생성 후에는 결과 데이터의 품질을 검토한다.

이 단계에서는 데이터를 바로 삭제하거나 병합하지 않는다. 중복 또는 반복으로 의심되는 후보를 리포트로 남기고, 사람이 확인한 뒤 유지/수정/삭제 여부를 결정한다.

검토할 내용:

```text
document_id 중복 여부
source + source_id 중복 여부
url 중복 여부
title 중복 여부
한 문서 안에서 같은 문장이 반복되는지 여부
문서 간 cleaned_text가 매우 유사한지 여부
mythology 데이터에서 description과 behavior/history/weakness가 반복되는지 여부
```

품질 검토용 파일:

```text
processing/check_processed_quality.py
```

생성할 리포트:

```text
database/processed/quality_report.md
```

중복 판단 기준:

```text
완전 중복
같은 document_id, 같은 source + source_id, 같은 url인 경우

강한 중복
title이 같고 cleaned_text도 거의 같은 경우

주제 중복
title이나 키워드는 비슷하지만 존재 설명, 이야기, 지역 변형처럼 역할이 다를 수 있는 경우
이 경우 바로 삭제하지 않고 검토 후보로만 남긴다.
```

특히 `ultimate_global_mythology_1000.json`은 `description` 안에 `behavior`, `history`, `weakness` 내용이 이미 포함되어 있을 수 있다. 품질 검토 결과 이 문제가 확인되어, 여러 필드를 단순 합치지 않고 processed의 `description`에는 원본 `description`만 저장하도록 수정했다. `behavior`, `history`, `signs`, `weakness`, `survival_rules`는 삭제하지 않고 `metadata`에 유지한다.

품질 검토에서 발견된 주요 이슈와 처리 내용은 `database/processed/quality_report.md`에 기록한다.
