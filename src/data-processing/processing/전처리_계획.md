# 데이터 전처리 계획

## 목표

현재 전처리의 1차 목표는 `database/data/dcinside_horror_filtered.json`만 정제해서 PostgreSQL 적재와 pgvector 임베딩에 활용할 수 있는 processed JSON을 만드는 것이다.

다만 프로젝트 데이터가 계속 바뀔 수 있으므로 `verified_korean_horror_master.json`과 `ultimate_global_mythology_1000.json`은 코드에서 완전히 삭제하지 않는다. 필요해지면 `preprocess_data.py`의 실행 플래그를 바꿔 다시 전처리할 수 있게 남겨 둔다.

`misin.json`은 현재 미신 문장 단순 적재용 데이터라 전처리 파이프라인에서 제외한다.

## 현재 데이터 판단

| 파일 | 데이터 성격 | 현재 처리 판단 |
| --- | --- | --- |
| `dcinside_horror_filtered.json` | DCInside에서 수집한 괴담/경험/창작 게시글 | 기본 전처리 대상 |
| `verified_korean_horror_master.json` | 검증된 괴담/도시전설 본문 | 보류. 나중에 플래그로 재활성화 |
| `ultimate_global_mythology_1000.json` | 요괴/신화 엔티티 설명 데이터 | 보류. 나중에 플래그로 재활성화 |
| `misin.json` | 짧은 미신 문장 목록 | 전처리 제외 |

## 전체 흐름

```text
database/data JSON 확인
→ analyze_raw_data.py로 구조 분석
→ 전처리 대상 결정
→ preprocess_data.py 실행
→ database/processed에 결과 저장
→ check_processed_quality.py로 품질 검토
```

## 1단계: 원천 데이터 분석

분석 스크립트:

```bash
python src/data-processing/processing/analyze_raw_data.py
```

분석 대상:

```text
database/data/dcinside_horror_filtered.json
database/data/verified_korean_horror_master.json
database/data/ultimate_global_mythology_1000.json
```

분석 제외:

```text
database/data/misin.json
```

`misin.json`은 현재 전처리할 본문형 문서가 아니라 PostgreSQL에 단순 저장하는 문장 데이터이므로 분석/전처리 후보에서 제외한다.

## 2단계: DCInside 전처리 정책

DCInside 원본 구조:

| 컬럼 | 예시 | 처리 방향 |
| --- | --- | --- |
| `title` | `[경험]`, `[괴담]`, `[창작]`, `[사건/사고]` | 게시글 분류값으로 사용 |
| `content` | 실제 게시글 본문 | 정리 후 `description`, `cleaned_text`로 저장 |
| `region` | `한국` 등 | metadata에 보존 |
| `source` | `dcinside_gongpow` 등 | source와 ID 생성 기준으로 사용 |

### 제목 처리

DCInside 데이터는 `title`이 실제 제목이 아니라 `[경험]` 같은 분류 태그인 경우가 많다. 따라서 태그는 제목으로 그대로 쓰지 않고 분류로 이동한다.

| 원본 태그 | 처리 분류 |
| --- | --- |
| `[경험]` | `WITNESS` |
| `[괴담]` | `WITNESS` |
| `[사건/사고]` | `WITNESS` |
| `[창작]` | `CREATION` |

태그를 제거한 뒤 제목이 비면 `content` 앞부분으로 임시 제목을 만든다.

### 본문 정리

`content`는 실제 본문으로 사용한다. 제거 또는 정리 대상은 다음과 같다.

```text
마크다운 링크
URL
HTML 태그
각주 번호
과한 공백
반복 줄바꿈
```

정리 전 본문은 `description`에 남기고, 정리 후 본문은 `cleaned_text`에 저장한다.

### 제외 기준

다음 행은 전처리 결과에서 제외한다.

```text
content가 비어 있는 행
title 태그로 WITNESS/CREATION을 판단할 수 없는 행
```

현재 데이터에서는 `content`가 비어 있는 행은 없고, 주요 태그는 `[경험]`, `[괴담]`, `[창작]`, `[사건/사고]` 네 가지다.

## 3단계: 보류 데이터 처리 방식

### verified_korean_horror_master.json

나중에 필요해지면 `preprocess_data.py`에서 아래 값을 바꿔 실행한다.

```python
PROCESS_VERIFIED = True
```

처리 기준:

| 컬럼 | 처리 방향 |
| --- | --- |
| `title` | 제목으로 사용 |
| `content` | 본문으로 사용 |
| `region` | metadata에 보존 |
| `source` | source와 ID 생성 기준으로 사용 |

### ultimate_global_mythology_1000.json

나중에 필요해지면 `preprocess_data.py`에서 아래 값을 바꿔 실행한다.

```python
PROCESS_MYTHOLOGY = True
```

처리 기준:

| 컬럼 | 처리 방향 |
| --- | --- |
| `name` | 제목으로 사용 |
| `description` | 본문으로 사용 |
| `origin`, `habitats`, `weakness` | metadata에 보존 |
| `source` | source와 ID 생성 기준으로 사용 |

## 4단계: 실행 설정

현재 기본 설정:

```python
PROCESS_DCINSIDE = True
PROCESS_VERIFIED = False
PROCESS_MYTHOLOGY = False
PROCESS_MISIN = False
```

즉, 그냥 실행하면 DCInside만 전처리된다.

```bash
python src/data-processing/processing/preprocess_data.py
```

기본 생성 파일:

```text
database/processed/dcinside_horror_processed.json
```

## 5단계: processed 공통 컬럼

전처리 결과는 다음 공통 구조를 가진다.

| 컬럼 | 의미 |
| --- | --- |
| `document_id` | source와 source_id를 합친 processed 내부 고유 ID |
| `source` | 원본 출처 |
| `source_id` | 원본에 ID가 없을 경우 해시로 만든 안정 ID |
| `title` | processed 검토용 제목. DCInside DB 적재 시에는 저장하지 않음 |
| `url` | 원본 URL. 없으면 빈 문자열 |
| `description` | 정리 전 원문 본문 |
| `cleaned_text` | 정리 후 본문 |
| `description_length` | 정리 전 본문 길이 |
| `cleaned_text_length` | 정리 후 본문 길이 |
| `removed_patterns` | 제거된 노이즈 규칙 목록 |
| `noise_types` | 원문에서 감지된 노이즈 후보 |
| `keywords` | 대표 키워드 |
| `keyword_count` | 키워드 개수 |
| `keyword_basis` | 키워드 추출 기준 설명 |
| `text_status` | 본문 사용 가능 상태 |
| `metadata` | 삭제하지 않고 보존할 부가 정보 |

## 6단계: 품질 검토

전처리 후 품질 검토를 실행한다.

```bash
python src/data-processing/processing/check_processed_quality.py
```

생성 파일:

```text
database/processed/quality_report.md
```

품질 검토에서는 데이터를 삭제하지 않는다. 중복 ID, 중복 제목, 반복 문장, 유사 문서 후보를 보고서로만 남긴다.

## 최종 결정

이번 전처리 기준은 다음과 같다.

```text
기본 전처리: dcinside_horror_filtered.json
보류: verified_korean_horror_master.json
보류: ultimate_global_mythology_1000.json
제외: misin.json
```

이 구조를 쓰면 지금은 DCInside만 깔끔하게 처리하고, 나중에 검증 괴담이나 요괴 데이터가 다시 필요해져도 코드 자체를 새로 만들지 않고 플래그만 바꿔 재사용할 수 있다.
