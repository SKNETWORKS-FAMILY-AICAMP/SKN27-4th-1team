01. Project Overview

프로젝트 개요

Django 기반의 괴담 및 금기 아카이브 플랫폼으로, 서비스 핵심 데이터는 PostgreSQL에 저장하고 지역·장소·괴담 관계는 Neo4j로 탐색합니다. LLM을 연동해 사용자가 직접 새로운 괴담을 창작하고 공유할 수 있도록 구성했습니다.

괴담 아카이브

괴담, 괴이 존재, 금기 지역별 괴담 데이터를 쉽게 검색하고 열람합니다.

생성형 콘텐츠

지역, 장소, 금기, 발생 조건등을 입력해 AI 괴담을 생성하고 평가 흐름까지 연결합니다.

커뮤니티

목격담과 창작담을 작성하고, 본인 글을 수정·삭제할 수 있습니다.

02. Background & Goals

개발 배경과 프로젝트 목표

해결하고자 한 문제
  • 지역 괴담과 금기 정보가 파편화되어 탐색이 어려움
  • 사용자가 직접 괴담을 창작하려고 할 때 시작하기 어렵다.
  • 지역별 괴담정보를 시각적으로 제공하지 않음
구현 목표
  • Django 기반 사용자 인증, 마이페이지, 열린 게시판 구현
  • PostgreSQL 기반 괴담/금기 데이터 저장과 검색 제공
  • Neo4j 기반 지역-장소-괴담 관계 탐색 구현
  • Groq/Ollama 기반 LLM 생성과 RAGAS 평가 흐름 구성
  • 터미널형 UI, 글리치, 음향 효과로 몰입감 강화
03. Concept

오래된 괴담 기록소에 접속하는 경험

괴이 기록 보관소는 단순한 정보 검색 사이트가 아니라, 사용자가 오래된 공포 기록을 열람하는 듯한 분위기를 느끼도록 설계

접속 경험

사용자가 일반 웹사이트가 아니라 오래된 기록 장치에 접속한 듯한 첫인상을 목표로 했습니다.

기록소 세계관

기록 열람실, 금기 자료실, 신규 기록실처럼 페이지 이름부터 프로젝트 콘셉트인 오래된 사이트에 맞췄습니다.

탐색 동기

괴담을 단순히 읽는 것이 아니라, 금지된 자료를 찾아 들어가는 흐름으로 서비스 몰입을 유도했습니다.

05. ERD

ERD 설계

PostgreSQL 핵심 테이블
  • 인증: `auth_user`, `django_session`
  • 아카이브: `horror_stories`, `myth_entities`, `superstitions`
  • 생성: `generated_stories`
  • 게시판: `post_post`, `post_like`
  • 보관함: `accounts_bookmark`, `generated_story_bookmarks`, `post_bookmarks`
주요 관계
  • 사용자 1명은 여러 생성 괴담, 게시글, 좋아요, 보관 기록을 가질 수 있습니다.
  • 게시글 1개는 여러 좋아요와 게시글 보관 기록으로 연결됩니다.
  • 생성 괴담 1개는 여러 생성 괴담 보관 기록으로 연결됩니다.
PostgreSQL은 서비스 운영 데이터의 저장과 조회를 담당하고, 지역과 장소의 관계 탐색은 Neo4j가 담당하도록 역할을 분리했습니다.

07. System Flow

시스템 흐름

요청 처리 흐름
  • 브라우저 요청을 config/urls.py와 각 app/urls.py에서 연결
  • views.py가 페이지 렌더링과 JSON API 응답을 처리
  • services.py가 DB 조회, LLM 호출, Neo4j 조회 로직을 담당
데이터 처리 흐름
  • PostgreSQL: 사용자, 게시글, 금기, 생성 결과, 보관함
  • Neo4j: 국가, 지역, 장소, 괴담, 신화 존재 관계 탐색
  • Groq/Ollama: 챗봇 응답, 신규 괴담 생성, 평가 보조
accounts archive generator post regions Groq Ollama Docker

10. Archive App

archive app: 아카이브 검색과 금기 조회

사용 기술
  • Django Template으로 기록 열람실과 금기 자료실 화면 구성
  • Django ORM으로 `horror_stories`, `myth_entities`, `superstitions` 조회
  • fetch 기반 내부 JSON API로 검색, 상세, 오늘의 금기 데이터를 전달
  • Session에 최근 검색 결과와 TTS 대상 본문을 저장
구현 포인트
  • 키워드 기반 검색 결과를 점수화해 상위 결과를 보여줍니다.
  • 기록 열람실은 LLM 응답을 통해 기록소가 안내하는 듯한 경험을 제공합니다.
  • 금기 자료실은 목록 영역만 내부 스크롤되도록 설계했습니다.
  • ElevenLabs TTS와 YouTube BGM으로 낭독 경험을 확장했습니다.
11. Generator App

generator app: AI 괴담 생성

7개 조건 입력 LLM 생성 JSON 파싱 생성 결과 출력 창작담 게시
사용 기술
  • Django View와 Service 분리 구조로 생성 요청 처리
  • `common.llm_factory`를 통해 Groq 또는 Ollama 모델 연결
  • LLM 응답을 JSON으로 파싱해 제목과 본문을 분리
  • `generated_stories` 테이블에 입력 조건과 생성 결과 저장
구현 포인트
  • 지역, 장소, 괴이 유형, 금기, 시간, 발생 조건, 결말을 입력값으로 사용합니다.
  • 출력 형식을 JSON으로 제한해 화면 표시와 게시판 연동을 안정화했습니다.
  • 생성 결과 영역만 내부 스크롤되도록 구성했습니다.
  • 창작담 게시 버튼으로 post app의 열린 게시판 작성 흐름과 연결했습니다.
12. Post App

post app: 열린 게시판과 창작담 공유

사용 기술
  • Django ModelForm과 JSON API로 게시글 작성, 수정, 삭제 처리
  • PostgreSQL `post_post`, `post_like` 테이블로 게시글과 좋아요 저장
  • Django 인증 객체 `request.user`로 작성자 권한 확인
  • Template과 JavaScript로 카드 펼침, 검색, 탭 전환 UI 구현
구현 포인트
  • 목격담과 창작담을 탭으로 구분하고 같은 게시판 화면에서 탐색합니다.
  • 작성자 본인에게만 수정과 삭제 버튼을 노출합니다.
  • 수정은 같은 카드 안에서 바로 입력창을 열어 처리합니다.
  • 창작담은 신규 기록실 생성 결과를 받아 게시글로 등록할 수 있습니다.
13. Regions App

regions app: 지도와 GraphDB 관계 탐색

사용 기술
  • Neo4j Python Driver로 GraphDB 연결과 Cypher 질의 실행
  • Region, Origin, City, Place, Story 노드와 관계 기반 조회
  • Django JSON API로 지역별 관계 데이터를 프론트에 전달
  • JavaScript로 지도 확대, 축소, 드래그, RESET 기능 구현
구현 포인트
  • 지도 핀 클릭으로 특정 지역의 괴담 관계를 조회합니다.
  • `ORIGINATED_IN`, `HAS_PLACE`, `OCCURRED_AT` 관계를 따라 탐색합니다.
  • 조회 결과는 우측 패널의 폴더 트리 형태로 표시합니다.
  • 선택한 기록은 모달로 전체 본문을 확인합니다.
지도 핀 선택 지역 API 호출 Neo4j 관계 조회 폴더 트리 표시 기록 본문 열람
14. Accounts App

accounts app: 인증과 마이페이지

사용 기술
  • Django 기본 User 모델과 auth 시스템 사용
  • Session 기반 로그인 상태 관리
  • CSRF Token으로 POST 요청 보호
  • `@login_required`로 마이페이지와 보호 기능 접근 제어
구현 포인트
  • 회원가입 시 아이디 중복, 비밀번호 확인, 이메일 입력을 검증합니다.
  • 로그인 성공 후 세션을 저장하고, 로그아웃 시 세션을 파기합니다.
  • 마이페이지에서 사용자 정보, 보관함, 내가 쓴 글을 조회합니다.
  • 회원 탈퇴 시 확인창을 거쳐 계정 삭제와 로그아웃을 함께 처리합니다.
